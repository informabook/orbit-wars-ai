# Data dictionary

All tables are comma-separated UTF-8 with a header. Existing Phase 2 tables retain their original bytes. Phase 3 projections are under `results/phase3/`. The [historical experiment manifest](results/phase3/EXPERIMENT_MANIFEST.json) records row counts, source fingerprints, projection scope and table fingerprints. Empty fields mean unavailable or inapplicable. A numeric zero is an observed stored value. Status strings describe what the archived logger recorded.

## Phase 3 outputs

Every run writes `manifest.json` with the configuration, dependency version, aggregate statuses and registered agent source hashes. `results.json` preserves structured data and `matches.csv` stores one row per actual attempt. The match seed requested and `applied_seed` are comparable. A mismatch is an error. `terminal_statuses` and `rewards` are seat-ordered arrays. Rewards are blank in CSV and null in JSON for failed attempts. `turns` counts post-initial steps. `duration_sec` includes setup, imports, and simulation. `reason` is a machine-oriented status or exception class in the matches table. In `stages`, it records threshold outcomes, failed matches or skipped stages. Phase 3 experiments stay separate from bundled measurements.

Replay-feature CSVs use `replay_id,label,weight` plus the feature columns in [V14 order](orbit_wars_research/ranker_v14.py). Labels are binary and weights are positive. Feature normalization and training run metadata are stored in the user's JSON model. Scoring output rows are zero-based and have sigmoid-transformed scores in [0,1]. The logits rank the same rows monotonically away from numerical saturation.
